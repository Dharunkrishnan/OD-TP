APPLICATION FLOW:
------------------
1. User opens /login.
2. Login form validates email/password.
3. Demo accounts are:
   - od@claimshield.demo -> OD permission
   - tp@claimshield.demo -> TP permission
   - both@claimshield.demo -> OD + TP permissions
4. For valid login, AuthProvider stores user in state/localStorage.
5. App redirects based on permissions:
   - OD user -> /od/dashboard
   - TP user -> /tp/dashboard
   - dual-access user -> /od/dashboard by default (or can switch modules)
6. Protected routes prevent unauthorized access.
7. Dashboard displays UI using mock data and frontend-only interactions.

AUTH LOGIC SUMMARY:
-------------------
- AuthProvider stores user info in localStorage with STORAGE_KEY = "claimshield-user"
- login(email, permissions, remember) sets user state
- logout clears localStorage and resets state
- resolveDashboardPath(user) returns the correct route based on permissions
- RequireAuth blocks unlogged users
- RequirePermission blocks access to other module routes
- PublicOnly prevents logged-in users from revisiting login screen
